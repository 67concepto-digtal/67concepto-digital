## 🛡️ SEGURIDAD ANTI-FRAUDES Y HACKEOS

```
Pepe, la realidad es que hay gente mala en internet.

TIPOS DE ATAQUES POSIBLES Y CÓMO LOS PREVENIMOS:

ATAQUE 1: ALGUIEN INTENTA ENTRAR CON CONTRASEÑA EQUIVOCADA

¿Qué hace el atacante?
├─ Programa de computadora intenta 10 millones de contraseñas
├─ Esperando que UNA sea correcta
└─ = FUERZA BRUTA

¿Cómo lo prevenimos?
├─ Regla 1: Después de 5 intentos fallidos = BLOQUEO
├─ Regla 2: Bloqueo por 30 minutos (atacante se aburre)
├─ Regla 3: Nos notifica intentó, revisamos logs
├─ Regla 4: IP del atacante se banea (no entra más)
└─ = IMPOSIBLE ENTRAR

───────────────────────────────────────

ATAQUE 2: ALGUIEN INTENTA LEER DATABASE DIRECTAMENTE

¿Qué hace el atacante?
├─ Intenta código especial para acceder a base de datos
├─ Ejemplo: "SELECT * FROM users" (SQL Injection)
└─ = ACCESO DIRECTO A TODOS LOS DATOS

¿Cómo lo prevenimos?
├─ Códigos peligrosos son BLOQUEADOS automáticamente
├─ Sistema valida todo input del usuario
├─ Base de datos no responde a comandos directos
├─ Sistema registra intento en logs
└─ = IMPOSIBLE ACCEDER

───────────────────────────────────────

ATAQUE 3: ALGUIEN INTENTA METER UN VIRUS

¿Qué hace el atacante?
├─ Carga archivo malicioso a plataforma
├─ Virus se propaga a otros clientes
├─ Roba datos o daña sistema
└─ = CONTAGIO

¿Cómo lo prevenimos?
├─ Todos archivos son escaneados (antivirus)
├─ Archivos sospechosos son bloqueados
├─ Validación de tipos de archivo (solo imagen, documento)
├─ Archivos guardados separados (no en sistema)
└─ = IMPOSIBLE PROPAGARSE

───────────────────────────────────────

ATAQUE 4: ALGUIEN INTENTA COLAPSAR SERVIDOR (DDoS)

¿Qué hace el atacante?
├─ Envía millones de requests al mismo tiempo
├─ Servidor sobrecargado = Cae
├─ Clientes no pueden entrar
└─ = NEGOCIO PARADO

¿Cómo lo prevenimos?
├─ Repartimos servidores en múltiples ubicaciones
├─ Si uno cae = Otros cargando
├─ Detectamos tráfico anormal = Bloqueamos
├─ CDN (Red de distribución) distribuye carga
└─ = IMPOSIBLE CAER

───────────────────────────────────────

ATAQUE 5: ROBO DE SESIÓN (Alguien roba tu login)

¿Qué pasa?
├─ Atacante roba cookie de sesión
├─ Puede entrar como si fuera tú
├─ Accede a todos tus datos
└─ = ACCESO NO AUTORIZADO

¿Cómo lo prevenimos?
├─ Cookies tienen tiempo de expiración (30 min)
├─ Sesiones se revalidan constantemente
├─ IP se monitorea (si cambia = reautentica)
├─ Dispositivo se verifica (mismo celular = confianza)
├─ Biometría como segunda confirmación
└─ = IMPOSIBLE FALSIFICAR SESIÓN

───────────────────────────────────────

ATAQUE 6: PHISHING (Email falso para robar datos)

¿Qué pasa?
├─ Atacante envía email "falso" desde 67-AI
├─ Dice: "Verifica tu cuenta, clickea aquí"
├─ Cliente clickea link falso
├─ Entra a página fake = Roba contraseña
└─ = SUPLANTACIÓN

¿Cómo lo prevenimos?
├─ Nunca enviamos "clickea aquí para verificar"
├─ Si enviamos link = Verificado (correo legítimo)
├─ DNS validado (email viene realmente de nosotros)
├─ Cliente avisado en app si hay intento
└─ = CLIENTE PROTEGIDO

───────────────────────────────────────

SEGURIDAD A NIVEL DE DATOS:

BLOCKCHAIN de transacciones:
├─ Cada transacción es registrada
├─ No se puede borrar o falsificar
├─ Auditoría completa siempre disponible
└─ = TRANSPARENCIA TOTAL

ENCRIPTACIÓN DE TRÁFICO (HTTPS):
├─ Todo dato entre celular/computadora y servidor: Encriptado
├─ Incluso si interceptan = Solo ven código
├─ Estándar: TLS 1.3 (último protocolo)
└─ = EN TRÁNSITO PROTEGIDO

SEGREGACIÓN DE DATOS:
├─ Datos cliente A: Nunca toca cliente B
├─ Servidores separados para cada uno
├─ Aislamiento a nivel de red
└─ = CONTAMINACIÓN CRUZADA IMPOSIBLE

───────────────────────────────────────

PREVENCIÓN DE FRAUDE EN PAGOS:

VERIFICACIÓN 3D SECURE:
├─ Cliente hace pago
├─ Banco envía código al celular
├─ Cliente ingresa código
├─ Solo así se confirma pago
└─ = IMPOSIBLE SIN AUTORIZACIÓN

VELOCIDAD DE TRANSACCIÓN:
├─ Sistema detecta: "Este pago es MUY rápido"
├─ Puede ser fraude = BLOQUEA
├─ Verifica con cliente antes de procesar
└─ = PREVENCIÓN PROACTIVA

MONTOS ANORMALES:
├─ Cliente gastó siempre $500/mes
├─ De repente intenta $50,000
├─ Sistema: "¿Esto es raro, confirma?"
├─ Cliente confirma o rechaza
└─ = VALIDACIÓN REAL

UBICACIÓN GEOGRÁFICA:
├─ Cliente siempre entra desde Argentina
├─ De repente alguien entra desde Nigeria
├─ Sistema: "Login de ubicación diferente, confirma"
├─ 2FA enviado al celular del cliente real
└─ = IMPOSIBLE SUPLANTACIÓN

TRANSPARENCIA CON CLIENTE:

✅ Alertas inmediatas si hay intentos de ataque

Si alguien intenta acceder = TÚ eres notificado en el acto.
Tu seguridad es nuestra PRIORIDAD #1"

= CONFIANZA CONSTRUIDA
```
